# だれの番？

iPadの教室用・生徒指名アプリ。設定した人数（1〜99人、初期値40人）の番号を独立に抽選します。外部ライブラリ、外部フォント、通信による番号生成、解析サービスは使いません。

## 使い方

1. 「抽選スタート」を押すと、番号が高速で切り替わり、徐々に減速して選んだ時間（3秒・5秒・8秒、初期値8秒）で確定します。人数と抽選時間は画面上部で変更でき、端末に保存します。抽選中は変更できません。
2. 音は初期状態でOFF。「音 ON」にすると切替に同期した短い電子音と、確定時のファンファーレが鳴ります。設定は端末に保存します。
3. 「もう一度ひく」で再抽選します。既出番号の除外はありません。同じ番号が続く場合もあります。
4. iPad Safariの共有メニュー →「ホーム画面に追加」。追加したアイコンから開くと独立したアプリ表示になります。対応ブラウザでは「全画面」ボタンも使えます。

抽選中は背景の明るさを固定し、数字を低輝度・低コントラストで表示します。数字が変わることを伝えるための演出で、毎回の数字を読み取る必要はありません。確定時は高コントラストの数字と静止した金色の枠で強調します。全面の白黒点滅や枠の点滅はありません。iPadの「設定 → アクセシビリティ → 動作 → 視差効果を減らす」が有効な場合、数字の高速表示と演出アニメーションを止め、8秒後に確定番号だけを表示します。その場合、切替ビープは鳴らず、音ONなら最後のファンファーレは鳴ります。

数字は画面に合わせた極太・大サイズです。8mでの実際の読みやすさはiPadの大きさ、照明、視力に依存するため教室で確認してください。必要に応じて大型画面へミラーリングしてください。

## GitHub Pagesで公開

この `classroom-draw` フォルダの**中身**をGitHubリポジトリのルートに置きます。`.github` も含めてください。

1. GitHubで新規リポジトリを作成します。
2. このフォルダをリポジトリとして登録し、`main` ブランチにpushします。既存リポジトリへ入れる場合も `package.json` と `.github` がルートに来るよう配置します。
3. リポジトリの **Settings → Pages → Build and deployment → Source → GitHub Actions** を選びます。
4. **Actions → Test and deploy to GitHub Pages → Run workflow** を実行します。その後はmainへのpushで自動公開されます。
5. Actionsのデプロイ結果に表示されたHTTPS URLをiPad Safariで開きます。通常は `https://ユーザー名.github.io/リポジトリ名/` です。

ワークフローはテスト合格後に `public/` だけを公開します。プルリクエストではテストのみ実行します。相対パスを使っているためリポジトリ名によるサブパスにも対応します。GitHubのリポジトリ作成・push・実際の公開は、この成果物の作成時には行っていません。

参考：[GitHub Pagesのカスタムワークフロー公式説明](https://docs.github.com/en/pages/getting-started-with-github-pages/using-custom-workflows-with-github-pages)

## ローカル起動・テスト

Node.js 22以上とPython 3を使用します。アプリ自体はビルド不要です。

```sh
npm test
npm start
```

`http://localhost:4173` を開きます。`index.html` をファイルとして直接開く方法には対応しません。LAN上のHTTP URLではPWA機能が使えない場合があります。iPadのPWA確認はHTTPSのGitHub Pages上で行ってください。

任意のブラウザ統合テスト：

```sh
npm install --no-save --package-lock=false playwright
npx playwright install chromium webkit
node tests/browser.mjs
```

別のターミナルで `npm start` を実行しておいてください。ブラウザテストは約45秒かかります。CIには依存追加不要のロジックテストを設定しています。

## オフラインと更新

HTTPSで初回読み込みすると必要なファイルを保存します。初回は通信を保ち、読み込み完了後に一度開き直してからオフラインで利用してください。音も端末内で生成するためネット接続は不要です。

更新時には `public/sw.js` の `CACHE` の末尾（現在`v4`）を `v5` などに変更してください。新しい版は開いているアプリのウィンドウ・タブをすべて閉じた後、再起動すると適用されます。ブラウザのストレージ消去・自動削除後は再度オンライン読み込みが必要です。

## 実装の要点・制約

- 最終結果は演出用の数字と独立に `crypto.getRandomValues` で選択。剰余の偏りを排除しています。
- Web Audio APIはユーザー操作内で初期化・再開。音OFFは再生中の音もミュートします。[MDN公式説明](https://developer.mozilla.org/en-US/docs/Web/API/Web_Audio_API/Best_practices)
- `performance.now()` を基準に8秒の期限を判定します。表示更新はブラウザの描画タイミングに従うため、通常は期限後の最初のフレームで確定します。
- 他アプリへ切り替えた場合は演出・音を止めます。8秒を過ぎて戻った場合は同じ事前選択済み結果を無音で表示します。
- 数字の高速変化は読み上げず、抽選開始と確定だけを読み上げます。タッチ、キーボード操作、画面回転に対応します。
- PWA、音の出力、ホーム画面追加、実際の8m視認性はiPad実機で最終確認が必要です。端末の音量や消音設定も確認してください。
